# 로컬 AI 프로젝트 묶기

프로젝트 묶기 기능은 선택한 폴더의 최상위 파일에서 관련성이 높은 파일 이름을 찾아 프로젝트별 폴더 구성을 제안합니다. AI 제안은 참고용이며, 사용자가 목록과 폴더 이름을 확인하고 **선택한 파일 묶기**를 눌러야 이동합니다. 이동은 기존 작업 기록을 사용하므로 작업 기록에서 되돌릴 수 있습니다.

## 분류 흐름

1. 기존 스캐너가 선택 폴더 바로 아래의 일반 파일을 확인합니다. 숨김 파일, 하위 폴더, 설정에서 제외한 항목은 분석하지 않습니다.
2. CleanFolder가 각 파일에 임시 ID를 붙이고, ID·파일 이름·확장자 기반 분류를 Ollama에 보냅니다.
3. 모델은 파일 이름과 종류에 뚜렷한 공통점이 있는 경우에만 그룹을 제안하고, 애매한 파일은 미분류로 남깁니다. 응답은 JSON Schema로 제한합니다.
4. CleanFolder가 응답의 ID가 입력 목록에 있는지, 중복 배정이 없는지 확인합니다. 폴더명에서 경로 구분자와 운영체제 예약 문자를 제거합니다.
5. 사용자가 파일 체크 상태와 폴더명을 검토한 뒤 적용하면, 기존 Core가 이동 직전에 폴더·파일 식별 정보와 크기·수정 시각을 다시 확인하고 이동 기록을 저장합니다.

파일명 기반 추론은 문서 내용 기반 분류보다 정보 노출이 적지만, 이름이 모호하면 정확도가 떨어질 수 있습니다. 현재는 모델이 내용을 읽거나 파일 이동 도구를 호출하지 않습니다.

## 로컬 모델 준비

1. Ollama를 설치하고 실행합니다.
2. 사용할 모델을 로컬에 준비합니다. 예:

   ```bash
   ollama pull qwen3:4b
   ```

3. CleanFolder의 **프로젝트 묶기** 화면에서 설치한 모델 이름을 입력합니다.

CleanFolder는 `127.0.0.1:11434`의 Ollama API에만 연결하며 HTTP 프록시 설정을 사용하지 않습니다. 설치된 모델 목록에서 선택한 이름을 확인하고, 모델 이름이나 목록에 `cloud`가 포함된 모델은 거부합니다. Ollama의 클라우드 모델은 로컬 API를 통해서도 호출할 수 있으므로 클라우드 이름을 차단합니다.

모델을 다운로드할 때 인터넷이 필요할 수 있지만, 로컬 모델이 준비된 뒤의 분류 요청은 이 앱에서 Ollama 로컬 주소로만 보냅니다. 로컬 Ollama 설치와 선택한 모델을 신뢰할 수 있다는 전제의 보호입니다. CleanFolder가 컴퓨터의 다른 프로그램이나 운영체제 자체의 네트워크 동작을 통제하는 방화벽은 아닙니다.

## 보내는 정보와 보내지 않는 정보

로컬 모델 입력에는 아래 정보만 포함합니다.

- 파일 이름
- CleanFolder가 확장자로 계산한 파일 분류
- 앱 내부에서 만든 임시 파일 ID

파일 내용, 파일을 담은 폴더의 전체 경로, 사용자 계정명, 파일 식별 정보(기기·inode), 파일 크기와 수정 시각은 모델 입력에 포함하지 않습니다. 파일 이름 자체에 민감한 정보가 있다면 로컬 모델이 읽게 되므로 이름도 화면에서 확인한 뒤 실행해 주세요.

모델을 처음 내려받을 때는 인터넷 연결이 필요할 수 있습니다. 모델 다운로드와 파일 분석은 별도 단계입니다. CleanFolder의 분석 요청은 로컬 Ollama 주소만 사용합니다.

## 보호와 한계

- CleanFolder는 제안된 파일 ID가 이번 분석에서 제공한 목록에 있는지 확인합니다.
- 같은 파일을 여러 프로젝트에 중복 배정한 응답은 적용하지 않습니다.
- 한 그룹에 파일이 두 개 미만이면 제안이나 이동 대상으로 적용할 수 없습니다.
- 모델은 파일 이동 도구를 받지 않습니다. 실제 이동은 사용자가 승인한 뒤 CleanFolder Core가 처리합니다.
- 제안 이름은 안전한 폴더명으로 정리하고, 이동 직전에 폴더와 파일의 식별 정보를 다시 확인합니다.
- 파일 이름만으로 프로젝트 관계를 판단하므로 잘못된 그룹이나 미분류 결과가 나올 수 있습니다. 적용 전에 파일 목록과 폴더 이름을 확인하세요.
- 한 번에 최대 80개 파일까지 분석합니다. 폴더 전체를 재귀적으로 살펴보거나 문서 내용을 읽지 않습니다.
